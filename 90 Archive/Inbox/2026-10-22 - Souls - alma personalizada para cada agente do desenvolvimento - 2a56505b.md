# Souls - alma personalizada para cada agente do desenvolvimento

## Conteúdo capturado

Opinião do usuário (2026-10-22, respondendo a uma entrevista sobre a reestruturação da skill `development-roadmap`), citação literal: "no futuro o conceito de Souls será implementado com uma "alma" personalizada para cada agente do desenvolvimento e o desenvolvimento via roadmap ira abraçar isso".

Decisão tomada na mesma conversa: a skill `development-roadmap` foi reestruturada para nomear explicitamente os papéis de agente de cada execução (orquestrador, planejador, implementador, revisor de tarefa, revisor final) e reservar um ponto de encaixe para uma soul por papel. Enquanto nenhuma soul estiver definida, valem os prompts padrão do plugin superpowers.

## Contexto

Sessão curadora do Second Brain em 2026-10-22: o vault virou repositório oficial das skills do Claude Code, o plugin superpowers foi instalado e a skill `development-roadmap` passou a delegar o planejamento e a execução de cada etapa ao superpowers, numa branch do roadmap e em lotes de etapas.

## Origem

- Conversa com o usuário no Claude Code, sessão iniciada na raiz do vault, 2026-10-22.
- Arquivos que já citam o conceito: `99 System/Skills/development-roadmap/SKILL.md` (§7, "Papéis e Souls") e `99 System/Skills/development-roadmap/references/template.md` (tabela de papéis do "Protocolo de execução").

## Por que registrar

É uma direção futura declarada pelo usuário que deve orientar a evolução da skill de roadmap e possivelmente de outras skills de desenvolvimento.

## Limitações e incertezas

- O usuário não definiu o que é uma soul: formato, conteúdo (personalidade, regras, conhecimento, modelo), onde fica armazenada, se é escolhida por papel, por projeto ou por agente, nem como se relaciona com os prompts do superpowers.
- "Cada agente do desenvolvimento" pode não coincidir com os cinco papéis nomeados na skill; a lista de papéis é escolha do agente.
- Nada além do ponto de encaixe foi implementado.
